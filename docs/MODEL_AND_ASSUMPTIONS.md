This is a required deliverable. It is the single most important document for the Transparency & Explainability criterion (30% of scoring). Write it so a policymaker with no technical background can understand what your tool does, what it assumes, and what it cannot tell them.

# Purpose and Scope

This tool estimates how housing production in Hawai'i would change under pro-housing zoning reforms, for policymakers evaluating reform options at the county and state level. Computation happens at the parcel level (using TMK parcels, county zoning, and the statewide State Land Use Districts layer) but every reported figure is aggregated to tract and county totals — parcel detail is drill-down only, never the headline output.

**In scope, implemented and verified end-to-end for all four counties (Honolulu/O'ahu, Kaua'i, Hawai'i County, and Maui County — Hawai'i County and Maui were added 2026-10-24; see Limitations for how their calibration confidence differs from Honolulu's/Kaua'i's):** a baseline (no-reform) scenario, plus five policy-intervention scenarios mapped onto Hawaii's actual zoning mechanisms — ADU/Ohana, Missing Middle upzoning, Transit-Oriented Density (both Honolulu's adopted city rezoning and the 2025 statewide FAR-bonus statute, modeled separately — see Methodological Approach), Parking Requirement Reduction, and Development Fee Reduction — each layered with optional feasibility and affordability gates. Honolulu's and Hawai'i County's and Maui's TOD/parking scenarios are only meaningful where each county actually has the relevant transit/parking data wired in — see Methodological Approach. **Out of scope:** any scenario not grounded in a real, cited Hawaii zoning/land-use category or statute; and, as of this writing, the live dashboard (`index.html`/`build_dashboard_data.py`) still only surfaces Honolulu and Kaua'i — Hawai'i County and Maui are built in the parcel/scenario pipeline (`scripts/build_model.py`) but not yet wired into the dashboard's per-county JSON output, a distinct remaining task. (The table immediately below is the original scenario-to-Hawaii-data design sketch, kept for its data-source citations; the implementation status above reflects the current, final state.)

- **Existing units** = count of `LEGDAT` rows sharing a TMK (each legal unit — e.g. each condo apartment — is its own row; a plain single-family parcel has exactly one row). Verified: 4,720 genuinely multi-unit TMKs out of 172,195, including condo towers over 300 units.
- **Improvement/vacancy proxy** = `ASMTPITT.buildingvalue` (assessed dollar value — same role as Hawaii County/Maui's `bldgvalue`, still not a square-footage figure).
- **Land-use class**: `ASMTPITT.ovrclass` exists but its numeric codes are **not yet decoded** — no coded-value domain ships with the field. Working hypothesis (unconfirmed): maps to Hawaii's standard 16-category statewide land-use classification. Needed before land-use-based eligibility (e.g. "currently single-family only") can be read directly off this field for Oahu; until decoded, eligibility there has to lean on zoning-district code instead.
- **"Zoning - Ohana"** (a Honolulu-specific layer, confirmed live) is a narrow regulatory overlay (130 features), **not** a citywide ADU-eligibility layer — don't use it to answer "which parcels can add an ADU," only to flag the specific areas it covers.

**Tax-class decoder — confirmed base scheme, but it does not solve the primary problem (2026-10-14):** sourced a citable base 1–9 tax-class code table from an official Honolulu Real Property Assessment tax-rate ordinance (same scheme, minor label variants, across all four counties — see data/DATA_SOURCES.md for the full table and citation). However, live-data analysis of the full `ASMTPITT` table (327,161 rows) showed:
- `ovrclass` is **blank for 90.0%** of rows (294,322/327,161). It is an *override* field, populated only when a parcel has two or more distinct tax-class sub-areas — it was never going to classify most parcels, override or not.
- The two dominant non-blank values (`'11'`, 30,502 rows; `'14'`, 2,048 rows) fall **outside** the base 1–9 scheme — they're newer categories (Honolulu has since added Residential A, Vacant Agricultural, Bed & Breakfast Home, Transient Vacation) that a current tax-rate document lists by name but without numeric codes. Working guess: `'11'` = Residential A, based on plausible scale — unconfirmed, not load-bearing on anything yet.

Net effect: `ovrclass` does not give usable primary land-use classification for Oahu, and the equivalent fields on the other three counties (`pittcode`, `taxclass`) were never run through this same gap-check. **This is why the project is moving the current-stock and land-use-eligibility problems onto different, more uniform data sources rather than continuing the county-by-county assessor-code chase** — see the next two sections.

## Current housing stock — now via HUD tract-level address data (added 2026-10-14)

Rather than continuing to chase inconsistent, partially-undecoded per-county assessor fields for *existing unit counts*, the model uses **HUD's Aggregated USPS Administrative Data on Address Vacancies** as the statewide current-stock baseline:

- **What it is:** a free (registration required, no fee) HUD/USPS dataset giving quarterly, census-tract-level counts of active, vacant, and no-stat residential and business delivery-point addresses, nationwide — Hawaii included. ([huduser.gov](https://huduser.gov/portal/node/1664), [2018 USPS FAQ](https://www.HUDUser.gov/portal/sites/default/files/pdf/2018-USPS-FAQ.pdf))
- **Why it's a good fit here:** it already reports at census-tract level — the Challenge's target aggregation — so there's no parcel-to-tract rollup to get wrong, and it applies *uniformly* across all four counties, unlike every assessor field we've chased so far.
- **The real caveat:** an "active residential address" is a USPS delivery point, not a certified housing unit count — a duplex with one mailbox undercounts, a commercial address occasionally miscodes as residential. It's a strong proxy for current stock, not a legal record of it.
- **Role in the model:** HUD tract counts become the **current-housing-stock denominator** feeding the Baseline scenario, and the cross-check for Oahu's LEGDAT-derived counts (LEGDAT stays in as a parcel-level validation/drill-down layer for Oahu specifically, where it already exists, but is no longer a dependency for the statewide number).
- **Access note:** the HUD USPS portal requires a login/registration, so this is a manual pull, not scriptable end-to-end like the ArcGIS layers. **In hand as of 2026-10-14** (`usps_vac_062026_tractsum_2kx.zip`, June 2026 vintage, 2020 census tract geography) — filtered to Hawaii (`geoid` starting `15`) and saved to `data/raw/hud_usps_tract_hi.csv`, 432 tracts. Sanity check: statewide active residential addresses (`ams_res`) sum to 631,002, in the right range for Hawaii's housing stock.

## Buildable-area methodology: parcel-level computation, bucketed rollup

Reform-capacity scenarios (Missing Middle, Parking Requirement Reduction, and any density-increase scenario) need *remaining* buildable area per parcel, not just current footprint. The chosen approach computes this at the parcel level and rolls up into **buckets**, not a single averaged ratio, because:

- **An averaged coverage ratio would misrepresent capacity.** Reform capacity is concentrated in a minority of underbuilt/vacant parcels; a tract average blends them with already-built-out parcels and erases exactly the signal a scenario needs to act on.
- **Bucketing matches the data's real precision.** Building footprints are ML-derived (see below) and noisy at parcel edges — a coverage ratio of 23% vs. 31% is noise-sensitive, but which band it falls in generally isn't.

**Pipeline:**
1. **Parcel level (per county):** spatial join of TMK parcels to building footprints; compute `coverage_ratio = Σ footprint_area / parcel_area` and `remaining_area = parcel_area − Σ footprint_area` per TMK.
2. **Bucket each parcel** on lot-size band (e.g. <5k / 5–10k / 10–20k / 20k+ sq ft), coverage band (e.g. 0–10% / 10–25% / 25–50% / 50–75% / 75%+), **and** zoning district + State Land Use District — the latter two aren't optional extra dimensions, they're what eligibility is keyed on anyway, so the bucket table is grouped by them from the start.
3. **Roll up** to `(tract or county) × zoning district × lot-size band × coverage band → parcel_count, Σ remaining_area`. This bucketed table — not raw parcel geometry — is what every scenario formula reads from: auditable, reproducible, and already at the Challenge's required aggregation level.
4. Scenario eligibility logic reads as, e.g., "Urban district, single-family zoning, lot-size ≥10k, coverage <25% → ADU-eligible" against the bucket table.

**Still open:** exact bucket boundaries (lot-size and coverage bands above are placeholders) and whether `remaining_area` needs a per-zoning-district coverage-ratio/setback adjustment rather than the flat `parcel − footprint` figure (same ordinance-text research flagged elsewhere in this document).

## `build_model.py` — implemented and verified for all four counties (Kauai 2026-10-14; Honolulu 2026-10-15; Hawai'i County and Maui 2026-10-24)

The pipeline above is now real code (`scripts/build_model.py`), not just a plan. Status: **all four counties verified end-to-end against live data.** Each county has its own `COUNTY_CONFIG` entry because the raw field names and ADU-eligibility rules genuinely differ per county (see `data/DATA_SOURCES.md`) — not a placeholder, a reflection of each county keeping its own schema and ordinance. One generic bug surfaced and was fixed while adding Hawai'i County: its raw parcel layer happens to carry its own field also literally named `zone` (a TMK administrative zone number, not a land-use zoning code), which collided by name with the separate zoning layer's own `zone` field during the merge and silently fed the wrong value into every zoning-dependent computation until caught by a 0-eligible-parcels sanity check — `build_county()` now explicitly drops any parcel-layer column that collides with `cfg["zoning_field"]`'s name before merging, a no-op for every county without that collision.

**What it does:** loads parcels + county zoning + statewide State Land Use Districts + Census 2020 tracts (added today — TIGERweb, Hawaii-filtered, 461 tracts) + building footprints, all reprojected to UTM Zone 4N (EPSG:32604) for consistent area math across the state. Joins each parcel to its zoning district, State Land Use District, and census tract by centroid-in-polygon (the standard approximation at this feature count — not full polygon overlay). Joins building footprints to parcels the same way, sums footprint area per parcel, and computes `coverage_ratio` and `remaining_area_sqft`. Buckets every parcel on lot-size band × coverage band × zoning × State Land Use District, and rolls up to tract level. Runs a first scenario (ADUs) against the bucketed table.

**Verified run, Kauai, 2026-10-14:** 25,119 parcels in, 25,119 out (no join-induced duplicates — fixed a boundary-coincidence double-count in both the zoning/SLUD/tract join and the footprint join, where a centroid landing exactly on a shared edge matched two polygons). Coverage ratio distribution: median 5.5%, IQR 0–27% — consistent with Kauai's largely rural, low-density character, not an artifact. ADU scenario: 10,000–11,000 eligible parcels statewide-for-Kauai, ~837 estimated new units at the placeholder 8% absorption rate — a sane order of magnitude for the county's housing stock, not implausible, but **both the eligibility rule and the absorption rate are placeholders, not sourced conclusions:**
- ADU eligibility used `ludcode == 'U'` (Urban district) + an existing-residential taxclass + lot size ≥ 7,500 sqft. **The 7,500 sqft minimum is an unconfirmed placeholder** — it has not been checked against Kauai's actual ADU ordinance (the same open question already logged above under the ADU scenario mapping).
- The 8% absorption rate is the same unsourced placeholder flagged in the Core Assumptions table below — not yet grounded in Hawaii permit-pace data.

**Known approximation, not yet addressed:** census tract count mismatch — TIGERweb returns 461 Hawaii tracts, HUD's USPS extract covers 432. Likely water-only or population-zero 2020 tracts with no USPS delivery points; needs confirming before the HUD stock numbers and this pipeline's tract output are merged.

Outputs land in `data/processed/` (gitignored, same as `data/raw/` — regenerate with `python scripts/build_model.py --county kauai`): `{county}_parcel_level.csv`, `{county}_bucket_rollup_tract.csv`, `{county}_adu_scenario_tract.csv`.

## Absorption-rate benchmarks, sourced (added 2026-10-14)

Rather than a single statewide default, each county/island gets its own empirical benchmark, computed as average annual building permits (2016–2025) ÷ 2023 housing stock, scaled to a 10-year horizon — the same kind of permit-pace calibration the El Paso build's documentation recommends, applied per island because Hawaii's islands diverge meaningfully in build pace (nearly 2x between Honolulu and Hawaii County):

| Area | 2023 housing units | Avg. annual permits (2016–2025) | Decade-equivalent rate |
| --- | --- | --- | --- |
| Statewide (default) | 572,063 | 3,849 | **6.7%** |
| Honolulu / Oahu | 376,209 | 1,886 | **5.0%** |
| Hawaii County (Big Island) | 91,546 | 1,006 | **11.0%** |
| Maui County | 73,563 | 764 | **10.4%** |
| Kauai County | 30,631 | 193 | **6.3%** |

Source: FRED Building Permits Survey series `BPPRIV015001` (Hawaii County), `BPPRIV015003` (Honolulu), `BPPRIV015007` (Kauai), `BPPRIV015009` (Maui), `HIBPPRIV` (statewide); housing-unit denominators from Hawaii DBEDT's `CO-EST2023-HU-15`. Full table at `data/reference/absorption_rate_benchmarks.csv`.

**What this is and isn't:** this measures total permits against total existing housing stock, not permits against an *eligible-parcel* universe under a specific reform — that historical baseline doesn't exist for Hawaii any more than it existed for El Paso before calibration. Treat these as defensible starting points for the slider, not as validated absorption rates for any one scenario. Honolulu's comparatively low rate (5.0%) likely reflects its much larger, more built-out existing stock rather than a slower construction *pace* in absolute terms (1,886 units/year is still the largest of the four) — a reminder that the ratio is stock-relative, not a measure of activity level on its own.

**Implementation:** `build_model.ScenarioParams(absorption_rate=None)` (the default) pulls the calling county's own benchmark via `absorption_rate_benchmark_for()`; passing an explicit value overrides it. This is the mechanism a future slider UI would call on every drag — see below.

## Scenario parameters as sliders, not fixed rules (added 2026-10-14)

Per your direction: rather than asserting one ADU eligibility rule, the model exposes the rule's components as adjustable parameters (`build_model.ScenarioParams`), so the tool can show how eligible-parcel counts and estimated capacity move as requirements change — which is the actual policy question ("what if the minimum lot size were lower/higher") rather than a single verdict.

Implemented now, Kauai-verified:
- **`min_lot_sqft`** (default 7,500, unconfirmed placeholder) — swept 5,000→15,000 sqft: eligible parcels range from 15,395 down to 3,020, a >5x spread. This is the parameter the real ADU-ordinance research (still an open item) should ultimately replace with Kauai's actual minimum, but the mechanism for varying it is now in place regardless of what that number turns out to be.
- **`require_owner_occupancy`** — Kauai's own tax-class field already distinguishes `OWNER-OCCUPIED` from `NON-OWNER-OCCUPIED RESIDENTIAL`, so this toggle works today with no new data: turning it on roughly halves eligible parcels (11,351 → 5,960 at the default lot size). Only Kauai has this distinction in its taxclass scheme right now (see data/DATA_SOURCES.md) — the other three counties' fields don't support it yet, and the code says so explicitly (`owner_occupancy_warning` in the returned metadata) rather than silently no-op'ing.
- **`absorption_rate`** — defaults to the county's own sourced benchmark above; overridable.
- **`require_parking`** — present as a toggle, but **not functionally implemented**: no county parking-ratio ordinance data has been sourced yet (same open item as the Parking Requirement Reduction scenario mapping above). Turning it on is recorded in the metadata with an explicit warning that it currently changes nothing, rather than pretending to apply an unsourced number.

The expensive spatial-join/bucketing step (`build_county()`) runs once per county; `run_adu_scenario()` re-applies these parameters cheaply against the already-bucketed table — the split a real slider UI would need, so flipping a toggle doesn't mean re-running the GIS joins.

## Kauai ADU ordinance — real numbers found, one correction (2026-10-14)

Pulled Kauai County's actual zoning code (Chapter 8, Article 15 reference via §8-1.4(i)/8-1.5, via eCode360) rather than continuing to guess. Confirmed, citable:

- **Max floor area: 800 sq ft** for a guest house/additional dwelling unit — this is a real, sourced yield assumption (replaces a planning-literature generic figure for this scenario specifically).
- **Parking: 1 off-street space required per unit**, separate from the primary dwelling's own parking. This is also the first real anchor number for the Parking Requirement Reduction scenario (below) — previously only a generic "need ordinance data" placeholder.
- **No owner-occupancy requirement.** The code requires common *ownership* between the ADU and primary dwelling (can't be sold separately, including via condominium property regime) but does not require the owner to live on site. **This corrects what I implied earlier** — I'd offered `require_owner_occupancy` as a slider without checking whether Kauai's real ordinance actually gates on it. It doesn't. The toggle stays in the model (it's a legitimate "what if a future ordinance required this" question, and other jurisdictions do condition ADUs on owner-occupancy), but it should not be presented as reflecting Kauai's current rule.
- **Eligible zones:** R-1 to R-6, R-10 to R-20, plus CN, CG, AG, and O — broader than the Urban-SLUD-only assumption `run_adu_scenario()` currently uses. Worth revisiting: the current `ludcode == 'U'` gate may be too narrow for Kauai specifically, since AG-zoned parcels outside the Urban district are explicitly eligible zones per this code section.
- **Still not found:** the per-district minimum lot area table (what "R-6" vs. "R-10" actually require in sqft) — the ecode360 pages that should hold this didn't render it in the sections fetched. The `min_lot_sqft` slider's 7,500 sqft default remains an unconfirmed placeholder; this is still the single open item before the ADU scenario can claim a sourced eligibility threshold.

**Acted on immediately:** replaced the `ludcode == 'U'` (Urban State Land Use District) eligibility proxy with the confirmed zoning-prefix list above (`COUNTY_CONFIG["kauai"]["adu_eligible_zoning_prefixes"]`) — a direct correctness fix, not a slider. Effect: eligible parcels rose from 11,351 to 13,727 at default settings, because AG-zoned parcels outside the Urban district (which the old proxy excluded) are explicitly listed as eligible in the real ordinance.

## Parking Requirement Reduction — first real implementation, Kauai (2026-10-14)

Built on the confirmed finding above: on Kauai, **parking does not gate ADU eligibility** — 1 off-street space is required either way under current code, so removing that requirement doesn't change *which* parcels qualify, it changes how much of each parcel's remaining area the requirement consumes. `run_parking_reduction_scenario()` reports that land-consumption figure (2,745,400 sqft statewide-for-Kauai at current settings) using a 200 sqft/space planning-literature assumption (not Kauai-sourced — same status as the 850 sqft/unit and 1,000 sqft/job figures the El Paso build flagged as generic benchmarks, not local data).

This is a narrower, more honest scope than the original mapping in the Baseline table implied ("need each county's current parking ratio by zoning district") — for Kauai's ADU case specifically, the ratio turned out to be a simple, confirmed constant (1 space/unit), not a per-district table requiring more ordinance research. Whether the same holds for *primary* dwellings (not just ADUs) under Missing Middle is a separate, still-open question.

## Density rule found — real numbers, two scenarios, one bug caught before it shipped (2026-10-14)

Kauai County Code §8-4.2(b) and §8-4.6 (confirmed via eCode360, pointed to directly): *"the number portion of each Residential Density District establishes the maximum number of dwelling units that may be permitted per acre of land."* I.e. R-6 allows up to 6 units/acre, R-20 up to 20, computed against the parcel's actual area, with §8-4.6(f) rounding a fractional result up at 65%+ of a whole unit. This is a real, generic rule — `max_density_units_per_acre()` parses the district number straight out of the zoning string via regex, so it works for every R-N value without a hardcoded per-district table (confirmed against R-15, which isn't individually named anywhere in the code).

**This replaces the flat 7,500 sqft placeholder for R-numbered districts.** The flat lot-size slider (`min_lot_sqft`) still applies, but now only as the fallback for the non-R zones that are ADU-eligible but have no units/acre figure (AG, O, CN, CG). Effect on the ADU scenario at default settings: eligible parcels dropped from 13,727 to **4,970** (density is a much stricter constraint than a flat 7,500 sqft minimum for low-density R-1/R-2 districts, which need a full acre or more per additional unit).

**Bug caught in the same pass, before it shipped:** the ordinance's "R-1 to R-6, R-10 to R-20" is a *numeric range*, not an enumerated list — it includes R-15 (between 10 and 20) and excludes R-7/R-8/R-9 (the gap between the two ranges). My first implementation matched literal zoning-code strings (`"R-1"`, `"R-2"`, … `"R-10"`, `"R-20"`) and would have silently excluded Kauai's 12 R-15 parcels from ADU eligibility. Caught by testing the eligibility function against R-7/R-8/R-15/R-40 directly rather than only checking that totals looked plausible — fixed to a numeric range check (`is_adu_eligible_zone()`) before this was reported as working.

**Missing Middle / Gentle Density — now implemented**, built directly on this density rule (R-numbered districts only; AG/O/CN/CG have no units/acre figure and are excluded from this scenario, not just unscored). Capacity per parcel = `min(max_units_by_density, 6) − existing_units_estimate`, capped at the Challenge's benchmark definition of 2–6 units regardless of what a district's density math alone would allow on a larger lot. At default settings: 3,160 eligible parcels, ~465 estimated new units (statewide-for-Kauai, at the 6.3% county benchmark absorption rate).

**Known limitation, not yet solved:** `existing_units_estimate` assumes exactly 1 existing unit on every already-residential parcel — there's no direct existing-unit-count field for Kauai (same gap that made Oahu's LEGDAT row-count discovery necessary). This overstates remaining capacity on any Kauai parcel that's already multi-unit. Also not yet reconciled: ADU and Missing Middle both draw on the same underlying district density allowance for a given parcel, so a combined headline number should take the **max** of the two scenarios per parcel, not their sum — consistent with the "never count the same physical capacity twice" rule the El Paso reference project uses. That reconciliation logic isn't written yet.

## Baseline vs. policy intervention — architectural correction (2026-10-14)

The user flagged a real gap in the framing above: **the Challenge requires establishing both a baseline (current law) and the policy interventions (changes beyond current law) — they are not the same number.** Up to this point, `run_adu_scenario()`'s "current-code-derived" eligibility rule (confirmed single-family zoning + the real density math) and its slider parameters were blurred together into one function, with no explicit separation of "what's already legal today" from "what a reform would add." That's a modeling error, not just a documentation gap — it would have reported a reform's *total* capacity as if it were the reform's *impact*, double-counting whatever capacity already existed under current law.

**Fixed via `ScenarioParams.is_baseline`:** `ScenarioParams()` with every field at its default now reproduces current Kauai County Code exactly — single-family-zoned (R-numbered) land only, the real density-per-acre rule, no owner-occupancy requirement, parking required as coded. This *is* the Challenge's required baseline, not an arbitrary starting point for sliders. Any non-default field (`allow_non_single_family_zones=True`, `require_owner_occupancy=True`, etc.) represents an actual policy intervention — a change beyond what current law allows.

**`run_adu_policy_impact()`** is the function that answers the Challenge's actual question: it runs the baseline and a given intervention, and returns their *difference* at tract level (`additional_eligible_parcels`, `additional_estimated_units`) — not either number standing alone. It refuses to run if the "intervention" params are identical to the baseline (nothing to measure the impact of).

Verified for the one intervention implemented so far — extending ADU eligibility to non-single-family zones (`allow_non_single_family_zones=True`, using AG/O/CN/CG with the flat `min_lot_sqft` slider, since those zones have no units/acre figure):

| | Eligible parcels | Estimated units |
| --- | --- | --- |
| **Baseline** (current code, single-family only) | 2,297 | 144.7 |
| **+ Intervention impact** (extend to AG/O/CN/CG) | +2,673 | +168.4 |

**This also corrected a related zoning-eligibility error, caught by the same user review:** an earlier pass had conflated ADU eligibility with the broader "guest house" accessory-use provision (§8-1.4(i)), which extends to AG/O/CN/CG — but ADUs specifically are single-family-zoned-land-only. `is_adu_eligible_zone()` no longer has a non-R fallback for the baseline; AG/O/CN/CG only enter the picture as an explicit, labeled intervention.

**Missing Middle got the same correction, and needed it more.** The scenario as first written used `min(max_units_by_density, 6)` as the *reform* capacity for every R-zoned parcel — but `max_units_by_density` is current law, not a reform. A parcel on a large R-20 lot that already legally allows 8 units today isn't a "Missing Middle" success story; that's baseline zoning doing its job. Split into:
- **`run_missing_middle_baseline()`**: already-legal capacity today (`max_units_by_density − existing_units_estimate`, uncapped at 6) — 3,160 parcels, 30,521 total units of capacity that current code already permits, no reform needed.
- **`run_missing_middle_scenario()`**: the actual reform, scoped to parcels that are *currently* single-family-restricted in practice (`baseline_capacity == 0` — today's density math on that parcel's actual area allows exactly the existing unit and no more). Only those parcels get upzoned to the Challenge's 6-unit benchmark ceiling. Result: 13,206 eligible parcels, +4,163.8 estimated units.

**That last number is large relative to Kauai's total housing stock (~30,631 units, 2023) — worth flagging rather than quietly presenting as settled.** 4,164 estimated units over the model's horizon is roughly 2.3x Kauai's actual decade-average permit pace (182 units/year × 10 ≈ 1,820). This is gross capacity × the county's absorption-rate benchmark, which is exactly the kind of result the absorption rate exists to temper — but the sheer size of the Missing Middle reform's theoretical unlock (every currently-1-unit R-zoned parcel gaining up to 5 more) means even an 6.3% absorption rate on that gross number still produces a figure worth independently sanity-checking in ArcGIS before trusting it, more than the smaller ADU numbers.

## Development Fee Reduction — deliberately NOT a production estimate (2026-10-14)

Unlike ADUs and Missing Middle, Development Fee Reduction doesn't change zoning eligibility — a lower fee doesn't make a parcel legally buildable that wasn't before, it changes project *economics*. Translating "fee reduced by $X" into "Y more units get built" requires a fee-elasticity-of-housing-supply estimate. Real research on this exists (e.g. RAND's 2024 impact-fee study, which found a 25% fee reduction "enables hundreds of new projects in high-cost cities"), but every estimate I found is city-specific and methodology-dependent — applying one to Hawaii would mean importing another market's elasticity and presenting it as if it were Hawaii's own number. I'm not doing that.

**What's implemented instead:** `run_development_fee_reduction_scenario()` takes any other scenario's tract-level output (ADU baseline, Missing Middle policy impact, etc.) and prices the Challenge's own standardized $50,000/unit assumption onto its *existing* unit-count column — a feasibility/dollar-savings metric layered on top of a unit count some other, eligibility-based scenario already produced, not a new production estimate of its own. Verified: $7.24M in fee savings on the ADU baseline's 144.7 estimated units; $208.19M on Missing Middle's 4,163.8 estimated units (same per-unit rate, scaled by each scenario's own unit count — the ratio between the two dollar figures is exactly the ratio between the two unit counts, confirming no hidden multiplier crept in).

**If a future pass wants production impact instead of just dollars:** the right next step is sourcing a Hawaii-specific (or at minimum California/high-cost-coastal-market) fee elasticity from the literature, citing it explicitly, and treating it with the same "this is someone else's number, not ours" caveat the absorption-rate benchmarks already carry — not inventing a plausible-sounding multiplier.

**What HUD data does *not* solve:** it tells us how many units exist, not what's legally buildable. Reform-capacity eligibility (is this tract currently zoned single-family-only, inside the Urban State Land Use District, etc.) still comes from the zoning/land-use spatial layers above — HUD is an additional, parallel input, not a replacement for the zoning overlay.

## Development feasibility (pro forma) research — inconclusive, 2026-10-14

Followed up on the fee-reduction gap above by looking for a real development pro forma to model feasibility, not just dollar savings. Findings:

- **Methodology found:** Terner Center for Housing Innovation (UC Berkeley), *"Making Missing Middle Pencil: The Math Behind Small-Scale Housing Development"* (June 2024). Full IRR-based pro forma: land cost/sqft + hard construction cost/sqft (by product type: duplex, fourplex-rental, fourplex-condo, multiplex) + a $40,000/unit impact-and-connection-fee assumption + financing (60% loan-to-cost, 9.5% construction / 6.5% permanent interest, 1.30 DSCR) vs. revenue (rent or sale price/sqft), tested against a 15% IRR-to-equity feasibility threshold ("pencils" or not). Includes an explicit fee-reduction sensitivity test: cutting fees $40k→$10k/unit raised IRR ~1–2 points — on its own, not enough to clear 15% for most California prototypes tested.
- **Problem: every input is California-specific** (East Bay/South Bay/LA/Sacramento submarkets). Applying Terner's cost and revenue numbers to Hawaii would mean importing another market's pro forma and presenting it as Hawaii's own — the exact thing this project has been declining to do for the fee-elasticity number.
- **Looked for Hawaii-specific substitutes, found them too thin to adapt responsibly:**
  - RLB's *Construction Cost Report – Hawaii Q3 2025* (rlb.com) confirms Hawaii construction costs rose 5.4% y/y (vs. 4.5% national) but the publicly fetchable page has no actual $/sqft figures by product type — those are in RLB's full PDF/NCCI index, not retrieved.
  - Title Guaranty Hawaii's Kauai EOY 2025 residential sales report gives a median Kauai single-family sale price ($1.2M, 423 sales) and vacant-land sale totals by district (Hanalei, Kawaihau, Lihue, Koloa, Waimea), but no land price *per square foot or per acre* — the figures needed to plug into a per-sqft pro forma aren't broken out at this level of the report.
- **Update, 2026-10-14: unblocked.** The user supplied the State of Hawaii OPSD's *"Financial Analysis of TOD Infrastructure Funding and Financing Options"* (HR&A Advisors, Group Pacific, PBR Hawai'i, CBRE, CoStar/Zillow as the underlying sources; July/Sept. 2023) — its Appendix "Real Estate Assumptions" table gives exactly what RLB's public page and the Kauai land-sales report couldn't: Kauai-specific (Lihu'e Town Core submarket) hard construction cost per GSF by product type, land price per SF, financing terms, developer profit margins, and market/affordable sale prices. Real numbers, not substitutes — see `KAUAI_LIHUE_PRO_FORMA_INPUTS` etc. in `build_model.py`.
- **The same report also gives a real, Hawaii-specific feasibility test**, used there for value-capture analysis rather than fee reduction: a project is feasible when its **"excess value"** — market value minus total development cost minus the developer's required return — is non-negative. A development fee is a cost line item in that same framework, so a fee reduction/elimination moves excess value dollar-for-dollar, with nothing else in the pro forma changing. `kauai_development_fee_reduction_feasibility()` implements exactly this.
- **Result, verified:** for a market-rate for-sale townhome in Lihu'e Town Core (Kauai's closest comparable submarket, closest product type to Missing Middle/ADU scale), the project is feasible even at the Challenge's full $50,000/unit fee (excess value +$129,618/unit) — removing the fee entirely only adds $50,000 more margin (+$179,618/unit), it doesn't change the feasibility verdict. For the affordable-sale version of the same product, the project is deeply infeasible either way (-$358,964/unit at full fee, -$308,964/unit with the fee eliminated) — a $50,000 fee cut is nowhere near enough to close that gap on its own. A low-rise (stacked/attached) for-sale product doesn't pencil in this submarket at either fee level. This directly confirms, with real Hawaii-specific numbers, the same conclusion Terner Center reached with California data: fee reductions move developer margin, but by themselves they don't decide whether a project gets built.
- **Explicit simplifications, stated rather than hidden:** (1) land cost is allocated as $/building-GSF from the source table, not a true site-area/FAR-based allocation (Kauai's Lihu'e-specific FAR/density standard isn't in this model yet); (2) financing cost uses a single average-outstanding-balance approximation, not the source's presumed full monthly draw schedule. Both are flagged in `kauai_development_fee_reduction_feasibility()`'s docstring — this is a transparent approximation of the real methodology, not a claim of matching HR&A/CBRE's model to the dollar.
- `run_development_fee_reduction_scenario()` (the original dollar-savings function) stays as-is for scenarios where only a unit-count estimate is available (ADU/Missing Middle tract rollups) — the two functions answer different questions and are both kept, cited separately.

## Feasibility toggle: zoning capacity vs. feasibility-adjusted units (2026-10-14)

Per the user's request, every scenario's eligible-parcel/unit-count output can now be gated by the development pro forma above, rather than treating "legally eligible" and "will actually get built" as the same number.

- **`tract_scaled_development_fee_reduction_feasibility()`** runs the Lihu'e Town Core pro forma once per Kauai census tract, scaling its reference sale price by that tract's own ACS median home value (B25077, 2022 5-year) relative to the Kauai countywide median ($742,900, verified live via Census API). This is a **linear scaling heuristic on the revenue side only** — hard cost, land cost, and financing stay fixed at the Lihu'e table's figures for every tract, since no tract-level cost data exists yet. A tract's land cost almost certainly differs from Lihu'e's too; scaling only revenue is a real, stated asymmetry, not a hidden one.
- **`apply_feasibility_gate()`** joins a scenario's tract-level output (ADU, Missing Middle) to that feasibility verdict and adds `feasibility_adjusted_units` — the same estimate where the tract's scaled pro forma clears, zero where it doesn't — while keeping the raw column untouched, so both numbers are always available together rather than one silently replacing the other.
- **Verified, Kauai countywide:** ADU scenario — 144.7 raw estimated units → 108.2 feasibility-adjusted (25% gated out, 3 of 17 tracts infeasible: tracts 403.01, 404.01, 409, 9400 — all below-countywide-median-home-value tracts where the scaled sale price doesn't clear the Lihu'e cost structure). Missing Middle — 4,163.8 raw → 2,937.6 feasibility-adjusted (29% gated out), using the same per-tract feasible/infeasible pattern.
- **Interpretation worth stating plainly:** every infeasible tract is a *below-county-median* home-value tract — i.e., the areas with the most existing zoning capacity for reform are not automatically the areas where that capacity is economically likely to be built, on these assumptions. That's a real, if simplified, policy-relevant finding, not an artifact of the toggle.

## Baseline/intervention principle confirmed as the general rule, not just ADU/Missing Middle (2026-10-14)

Per direct instruction: every scenario must model the effect of a reform *beyond* what current code already allows, never current-code capacity relabeled as reform impact. This is already the architecture behind `ScenarioParams.is_baseline`, `run_adu_policy_impact()`, and the Missing Middle baseline/scenario split above — it is the governing principle for every scenario in this model, including Transit-Oriented Density once Honolulu's county config exists (see below), not a one-off fix specific to ADUs.

**Missing Middle's setback/coverage exemption is the Challenge's own text, not an assumption made here.** The Challenge defines the scenario as: *"Teams may assume that setback and lot coverage requirements do not constrain the development of 2–6 units on a parcel currently restricted to single-family use."* `run_missing_middle_scenario()` already doesn't apply any footprint/coverage constraint to eligible parcels — this was previously an implicit simplification; it is now a cited compliance fact, not a shortcut.

**Transit-Oriented Density — exact Challenge language logged for the eventual Honolulu build:** *"Model the effect of increasing allowable residential density near major transit stops through higher building heights and/or increased floor area ratios. Teams should define major transit stops and justify their transit proximity threshold. Teams may assume that parking requirements are reduced or eliminated."*

**Update, 2026-10-14: checked the State's own TOD program materials** (planning.hawaii.gov/lud/state-tod/ — the Office of Planning and Sustainable Development's State TOD Program hub) rather than assuming the National Transit Database route was the only option. This closes the "justify a proximity threshold" requirement with the state's own standard instead of one this project would otherwise have had to pick and defend itself:
- **Defining TOD** (planning.hawaii.gov/lud/state-tod/defining-tod/) states the state's own working definition and proximity focus: TOD is "an area with a mix of residential, commercial, and institutional uses that is designed to maximize transit options," typically focused "within a half mile of a transit facility (about a ten minute walk)."
- **Station Area and Corridor Maps** (planning.hawaii.gov/lud/state-tod/station-area-and-corridor-maps/) confirms the state draws its own official TOD station-area boundaries at that same **half-mile radius**, around all 21 Honolulu rail (Skyline) stations: East Kapolei, UH West Oahu, Hoopili, West Loch, Waipahu Transit Center, Leeward Community College, Pearl Highlands, Pearlridge Center, Halawa Makai, Pearl Harbor Naval Base, Honolulu International Airport, Lagoon Drive, Middle Street, Kalihi, Kapalama, Iwilei, Chinatown, Downtown, Civic Center, Kakaako, Ala Moana.

The OPSD hub also links several deliverables not yet reviewed in detail (the State TOD Strategic Plan, a 2026 Skyline TOD Feasibility Study, and a 2023 TOD Infrastructure Finance report) that may carry station-specific density/FAR figures worth checking before the Honolulu baseline is built — flagged as the next TOD research step, not yet done. **(This entry is historical — as of the Honolulu-build entries later in this document, Honolulu is fully built out, the Skyline TOD Feasibility Study has been reviewed in detail and used for the rental feasibility test, and the real GTFS feed superseded the 21-station list as the TOD mechanism's actual input.)**
- TOD still gets the same baseline/intervention split as every other scenario when built: baseline = current density/height/FAR within that half-mile radius, intervention = the increase the reform allows, with parking assumed reduced/eliminated per the Challenge's own text rather than modeled as a constraint.

## Parking Requirement Reduction — what developers actually build post-reform, 2026-10-14

User-supplied source: Sohoni & Lee, *"Parking the Minimum Parking Requirement: Evidence from Nine U.S. Cities,"* *Journal of Planning Education and Research* 46(1), 2025 (DOI [10.1177/0739456X251343047](https://doi.org/10.1177/0739456X251343047)) — a quasi-experimental study of nine U.S. cities that removed minimum parking requirements citywide, in central districts, or along transit corridors.

**What's available vs. paywalled.** The abstract and a secondary citing source (a June 2026 UCLA Center for Parking Policy issue brief) give directional findings but not a clean "developers provide X spaces/unit absent a minimum" ratio — the paper's own results tables (Figure 1: % change in new parking provision relative to the former minimum, by city) are behind SAGE's paywall and weren't reachable here:
- Effects depend heavily on market demand and the existing policy environment — car-oriented, low-density cities saw little to no significant change; cities that removed minimums specifically in low-demand districts saw the largest reductions.
- Across 12 cities/areas examined (the nine-city study plus related cases cited in the same brief), 9 saw an overall decline in new parking supply post-reform and 3 saw an increase.
- In San Francisco and Buffalo (both citywide repeals), reductions in core/downtown areas were 1.5–1.9x larger than in the rest of the city — i.e., removing the minimum doesn't produce zero parking, and the effect is spatially uneven within one city, let alone transferable to Kauai as a single ratio.
- Mixed-use projects provided less parking than purely residential projects in the four CBDs where that breakdown was reported.

**Update, 2026-10-14: got the full PDF, plus a concrete transferability test using real ACS data.** The full text (Sohoni & Lee 2025) gives:
- **Table 3** — exact pre/post parking supply (as % of the former minimum) for all nine case cities. Honolulu is one of them (TOD-district reform: 89%→75% of MPR, treatment; control group rose 78%→106% over the same period) — real, same-state evidence, though it's an Oahu TOD-district result, not directly transferable to Kauai's ADU/parking context.
- **Figure 4** — two regression lines explaining the size of each city's reduction: % non-car commute share in the deregulated zone (R²=0.168) and mean block-group population density there (R²=0.317). Both positive: denser, less car-dependent places cut parking supply more.
- **p.98, in the authors' own words:** "Grand Rapids and Hartford, which experienced minimal policy effects, rank very low in density and very high in car dependency."

This is exactly the transferability test the user proposed: pull Kauai's own ACS commute-mode and density figures and see where it falls relative to the study's cities, rather than importing a number blind. Implemented in `fetch_data.py --layer acs_commute_density --county <county>` (tract-level ACS B08301 commute-mode-to-work + B01003 population, joined to TIGERweb tract land area already on hand; requires a free Census API key in `CENSUS_API_KEY`, not optional the way the other ArcGIS pulls are — the Census API returns an HTML "Missing Key" page for every vintage without one) and `build_model.kauai_parking_reform_context()` in `scripts/build_model.py`.

**Result, verified against live 2022 ACS 5-year data:** Kauai's population-weighted non-car commute share is **~5.4%** and its population-weighted density is **~675 people/sq mi** countywide. Both sit below the study's own "minimal effect" anchor cities (Grand Rapids, Hartford) — and the comparison is already generous to Kauai, since the study's axis is density/commute share *within the deregulated zone itself* (i.e., the built-up area being upzoned), not a countywide average diluted by Kauai's large rural/agricultural tracts.

**Why this is a scale question, not just a geography question (user clarification, 2026-10-14):** the mechanism behind *any* parking-reform effect — in Sohoni & Lee's nine cities and on Kauai alike — is that parking only changes outcomes where it's actually competing with buildable area for land. On a typical single-parcel ADU addition, 1 required space (≈200 sqft, this model's placeholder) is a small fraction of most eligible lots' remaining buildable area; removing that requirement rarely unlocks anything, because parking usually isn't the binding constraint there in the first place. A quick check against live Kauai parcel data confirms this isn't close for most ADU-eligible parcels — the median ADU-eligible parcel has plenty of room regardless of lot-size band — but the *distribution* is skewed by a real subset of small/already-built-out lots where parking is the difference between a unit fitting and not. The pattern that actually matters, and the one worth stating plainly rather than papering over with a single average:
- **Small-scale (ADU on an existing single-family lot):** parking reform is a rounding error for most eligible parcels, with a real but narrow tail of small or already-dense lots where it's the deciding factor.
- **Larger-scale (Missing Middle's 2–6-unit buildings on a parcel being upzoned):** parking's bite scales with unit count — 2–6 required spaces instead of 1 is a much bigger chunk of a parcel's buildable envelope than one ADU space ever is — so this is where removing the requirement is actually expected to matter, consistent with the ACS/study comparison above showing Kauai's *county-wide* car-dependency profile limits how large that effect can be even there.
- **Scope note:** `run_parking_reduction_scenario()` currently only scores the ADU-scale case (it's built on `run_adu_scenario()`'s eligible-parcel set). Extending it to score the Missing Middle-scale case — where, per the logic above, the effect is actually expected to be more than a rounding error — is a documented next step, not yet implemented.

**Decision: still don't manufacture a specific spaces/unit assumption.** Reading a precise reduction ratio off a regression with R²=0.168–0.317, for a geography sitting outside the sample's own range on both axes, would be extrapolation dressed up as a data-driven number — the same discipline this project has applied to the fee-elasticity and pro forma questions above. What the real data *does* support, and is now the documented position: expect little to no reduction in parking actually built on Kauai even if the minimum is removed, consistent with (not contradicted by) `run_parking_reduction_scenario()`'s existing approach of reporting land consumed under the current 1-space/unit requirement rather than assuming a reduced-but-nonzero post-reform figure. `kauai_parking_reform_context()` surfaces this verdict, the real ACS figures, and the study's city benchmarks directly in the scenario's metadata — not a silent assumption.

## Transit-Oriented Density — bus-corridor scenario, Kauai, and an open density-target question (2026-10-14)

**Scope correction.** An earlier draft of this scenario scoped TOD to Honolulu's rail stations (the Iwilei-Kapālama TOD Pilot Area, 27,400-unit HHFDC/DAGS Master Plan target). The user corrected this directly: *"there's nothing that says it has to be built around transit stations. If the counties have rapid transit we could base it around bus lines... the reason I shared those deliverables is to show you that some analysis had been done. Not to make it a constraining factor."* The Challenge benchmark itself says "major transit stops," not "rail stations" — so this scenario is built on Kauai Bus's real GTFS feed instead, for the one county (Kauai) already fully modeled here.

**Major transit stop, defined from real data, not assumed:** a Kauai Bus stop served by 2+ distinct weekday routes (58 of 126 weekday-served stops). Kauai Bus has no rail or BRT — its network is a hub-and-spoke of single-route shuttle loops feeding a handful of mainline/transfer stops (e.g. Kukui Grove – First Hawaiian Bank: 9 routes, 109 weekday trips). Route count is a clean, real, data-driven line between a trunk/transfer stop and a stop only one shuttle loop ever reaches. See `fetch_data.py:fetch_kauai_bus_major_stops()`.

**Proximity threshold:** half a mile ("about a ten-minute walk") — the State of Hawaii TOD Program's own station-area standard (planning.hawaii.gov/lud/state-tod/), stated in mode-agnostic terms ("transit facility") and extended here from rail to bus stops on that same reading.

**First attempt and why it needed a second factor.** Stop-proximity alone flagged 10,097 of Kauai's 25,123 parcels (~40% of the county) — because Kauai Bus's mainline routes run through essentially every town, "near some major stop" isn't a geography that concentrates anything. The user caught this directly: *"This needs to be a zoning standard applied uniformly so doing a stop-based analysis isn't helpful. What if it was transit stops plus some type of street designation, like high frequency transit along major corridors? That would allow us to focus high density along only certain corridors."*

**Corridor requirement, added in response.** A parcel is now TOD-eligible only if it's within a half mile of BOTH a major stop AND a Principal- or Minor-Arterial road segment, per HDOT's own federal functional classification (HPMS Roads layer, `f_system_t` field — a real, statewide-applied standard, not a threshold invented for this project; see `fetch_data.py:fetch_kauai_arterial_roads()`). On Kauai this resolves to Kuhio Highway and Kaumualii Highway — the island's two cross-island trunk roads — and their immediate approaches.

**Honest result: the corridor requirement narrowed eligibility only modestly, because Kauai's settlement pattern is linear along the highway.** 9,428 parcels remain eligible at the half-mile/half-mile combination (vs. 10,097 for stop-proximity alone) — not a dramatic reduction. Tightening the corridor buffer narrows it further (quarter mile: 6,587 parcels; eighth mile: 3,870) but even the tightest tested still leaves thousands of parcels eligible, because most of Kauai's existing development already sits directly on or near its one real highway corridor. **Geography isn't the dominant lever on this scenario's output — the density figure is.**

**The still-unresolved problem: the density target.** The only real, cited Hawaii TOD density figure found anywhere in this project's research is ~50 units/gross acre — HHFDC/DAGS's Master Plan target for Honolulu's Iwilei-Kapālama TOD Pilot Area (OPSD TOD Infrastructure Finance Deliverable 1), a 552-acre Oahu rail-corridor *redevelopment* district. No Kauai-specific or generic-Hawaii bus-corridor TOD density standard was found in the OPSD deliverables, the State TOD Program page, or elsewhere. Applied to the current (half-mile/half-mile) eligible footprint, it produces ~512,000 units of pre-absorption zoned capacity against only ~8,300 existing units on that same land — and even after this project's absorption-rate discount (6.3%/yr), ~28,500 "new units," more than the county's entire existing housing stock (19,413 units). **That is not a credible number, and this project is not going to round it into something that looks more plausible without a real source.** `build_model.TOD_DENSITY_TARGET_CAVEAT` carries this caveat into every scenario output that uses the figure.

**Feasibility-gate result — tested the user's stated hypothesis directly, and it came out false for an instructive reason.** The user hypothesized: *"if we apply development feasibility it would probably negate TOD in a lot of these areas."* Running this scenario through `tract_scaled_development_fee_reduction_feasibility()` / `apply_feasibility_gate()` zeroed out only the same 4 (of 15) tracts the Missing Middle and ADU scenarios already fail on — a ~22% reduction, not the "negate TOD in a lot of areas" the hypothesis predicted. This is **not** evidence that TOD at this scale is actually feasible: the feasibility gate it was tested against is the Development Fee Reduction scenario's pro forma, built around a Lihu'e Town Core *townhome resale* product — it has no way to flag a 50-units/acre multifamily redevelopment assumption as unrealistic, because its cost/revenue structure was never built to price that product type. The honest read is that this particular test doesn't bear on the density-target problem at all, not that the density target survived scrutiny.

**Parking:** the benchmark allows teams to "assume that parking requirements are reduced or eliminated" for this scenario — not separately modeled as a constraint here (same gap as the Parking Requirement Reduction scenario's own data limitation), consistent with that allowance.

**Open decision, not yet made:** either (a) replace the 50 units/acre figure with something scaled to Kauai's own built context (e.g. derived from the island's highest existing R-district, R-20, rather than importing an Oahu redevelopment-pilot number), keeping the Iwilei-Kapālama figure only as cited background context rather than a model input; or (b) tier the density step-up by stop strength (a materially higher ceiling only within a tight radius of the handful of highest-volume hub stops, a smaller step-up across the broader corridor) so the number reflects where a bus network's actual carrying capacity differs, not a flat island-wide ceiling. Either fix should land before this scenario's unit totals are reported as a real estimate rather than an illustrative upper bound.

### Update, 2026-10-15: both open items resolved with real Hawaii TOD policy mechanics, not a guess

**Proximity threshold switched to three-quarter mile.** Checked a second, more authoritative source specifically for a statewide density/proximity standard: OPSD's *Toward a Transit-Oriented Development Housing Investment Strategy* (SCR162 report, Dec. 2023). It confirms **no Hawaii document states a numeric statewide TOD density standard**, for rail or bus — the half-mile figure used previously is Honolulu's own City TOD Special District standard (HRO §21-9.100-9, "TOD Station Area"), stated for RAIL stations specifically. What this report does give, genuinely mode-agnostic: it maps TOD areas statewide using a **¾-mile buffer around both rail and bus routes/stations/hubs**. Switched `THREE_QUARTER_MILE_METERS` to this figure for both the major-stop and arterial-corridor buffers, since it's the one real standard built for exactly this (bus-inclusive) case rather than a rail standard stretched to cover buses. Combined eligibility: 13,004 parcels (up from 9,428 at the half-mile/half-mile combination — the wider buffer, as expected, picks up more).

**Density mechanism replaced: a multiplier on each parcel's own zoned density, not a flat absolute ceiling.** Rather than picking a different flat number (Kauai's own R-20, or a stop-strength tier — the two options floated above), checked Honolulu's actual TOD Special District zoning code (Honolulu Revised Ordinances §21-9.100-8, "General requirements and development standards"). It does not set a flat density figure at all: it sets a **multiplier on whatever density/FAR the underlying zoning district already allows** — 1.2× with a minor TOD special district permit, up to 2.0× with a major special district permit or PD-T approval. This is a real, citable Hawaii TOD zoning *technique*, and it structurally fixes the magnitude problem the flat 50-units/acre figure caused: `build_model.TOD_DENSITY_MULTIPLIER = 2.0` now multiplies each Kauai parcel's own existing `density_per_acre` (the same real district density rule ADU and Missing Middle already use), so a rural R-2 parcel and an R-20 parcel get proportionally different TOD capacity instead of an identical Oahu-urban-redevelopment-scale ceiling. Scope limitation carried over from ADU/Missing Middle: only applies to R-numbered districts, which are the only ones with a `density_per_acre` figure to multiply; AG/O/CN/CG parcels get no TOD capacity.

**Result: a credible number, for the first time.** With both fixes applied: 2,571 pre-feasibility estimated units (down from ~28,500), and 2,145 after the feasibility gate — now the same order of magnitude as the Missing Middle scenario (4,164) and well under the county's existing housing stock (19,413), rather than exceeding it. The feasibility gate's own limitation stands as previously documented (it's still pricing a townhome-resale product, not the mid-rise rental product a 2× density multiplier implies in the densest R-districts) — see the open item below on building a real rental pro forma.

### Update, same day: superseded again by an ENACTED statute — and the magnitude problem came back, worse

The user supplied two 2025 Hawaii legislative bills (HB1409 and its companion SB1614) that set a real, prescriptive TOD density standard: **HRS §206E-246(j), "transit-supportive density,"** a floor area ratio (FAR), not a units/acre figure or a multiplier on existing zoning — **base FAR ≥ 4.0** for any county-designated TOD area or underlying zoning (whichever is higher), **FAR ≥ 6.0** within ½ mile of a "locally preferred alternative" transit station, **FAR ≥ 7.0** (or the applicable TOD plan/special-district max, if higher) within ¼ mile. HB1409 actually passed — **Act 159 (2025)**, current law; SB1614 carried the identical tiers but died in committee and was carried over to 2026. Both bills are mode-agnostic in wording ("mass transit project," "public transit systems," never "rail"), consistent with this scenario's bus-corridor scope, though whether a bus corridor can reach the higher 6.0/7.0 tiers turns on the undefined term "locally preferred alternative" — genuinely untested either way.

This superseded the Honolulu-ordinance multiplier above: `run_tod_scenario()` now takes `far` directly (default 4.0, the statute's base tier), converting FAR to units via `floor_area_sqft = parcel_area_sqft * far`, `units = floor_area_sqft / 840 sqft` (reusing the Lihu'e lowrise product's unit size — a stated assumption, not a TOD-specific source). Per the user's explicit design choice, this is exposed as a single slider value rather than computed per-parcel distance tiers, and — because the statute applies "for all uses permitted... under underlying county zoning," not just R-numbered districts — TOD capacity is no longer restricted to R-zoned parcels the way ADU/Missing Middle are.

**Honest result: even the statute's own base tier is implausible at this eligibility footprint.** FAR 4.0 applied to Kauai's median parcel (~11,350 sqft) implies ~54 units on a single quarter-acre lot. Across the 13,004 TOD-eligible parcels, that's **267,734 pre-feasibility estimated units** — an order of magnitude worse than the previous (also-implausible) 50-units/acre result, and the feasibility gate only brings it to 190,779, still absurd. This is not evidence against the statute's own figures, which are real and enacted — it's evidence that **the structural problem all along has been the eligibility footprint, not the specific density number.** Three different real, independently-sourced Hawaii TOD density mechanisms have now been tried (an Oahu pilot's absolute target, Honolulu's own TOD-ordinance multiplier, and now a state statute's FAR tiers), and all three produce an implausible result when applied blanket across ~13,000 parcels (over half the county). Every real Hawaii TOD density standard found so far was written for a small, specifically-designated station-area overlay (a few hundred acres, a handful of rail stations) — not a corridor this broad on an island whose towns are strung along one highway. **This is presented in the dashboard deliberately unresolved** (a FAR slider the user can drag, with an explicit on-page warning), rather than picking a fourth number and hoping it lands better — the next real fix is narrowing eligibility itself (e.g. to a tighter radius of the handful of highest-ridership hub stops specifically, closer to how real station-area overlays are drawn), not the intensity figure.

## Affordability-constrained demand — the third gate, distinct from feasibility (2026-10-15)

The user's own framing: "zoned capacity" and "feasibility" are both supply-side questions (can a parcel legally hold more units; would a developer profitably build them at the comps-implied price), and the model was missing a genuinely different, demand-side question — *of the households who actually live in a tract, how many could afford the unit a feasible project would produce?* A tract can clear the feasibility bar (a developer's return pencils at the going price) while still being a market of a handful of local households who could ever pay that price. The two gates answer different failure modes and have to be reported separately, not folded into one verdict.

**Mechanism**: `build_model.tract_affordability_constrained_capacity()` takes the feasibility gate's own comps-implied price per tract (`scaled_sale_price_usd` for ADU/Missing Middle's for-sale product; the single countywide Zillow ZORI figure for TOD's rental product — see the ZORI section above) and backs out the household income required to afford it under standard underwriting: 20% down, 30-year fixed, and the HUD/Census-standard 30%-of-gross-income affordability threshold. The mortgage rate is real, not assumed — **7.000%, the median 30-year fixed rate across eight Hawaii-market lenders quoted at [HiCentral (Honolulu Board of REALTORS)](https://www.hicentral.com/hawaii-mortgage-rates.php), confirmed live 2026-10-15** (one outlier, an Alaska-based credit union quoting 9.625%, excluded as not a Hawaii-market lender). That required income is then checked against the tract's own ACS B19001 household-income distribution — 16 real income brackets, newly pulled (`fetch_data.py --layer acs_income_distribution`), not the tract median used as a stand-in — via linear interpolation within whichever bracket the threshold falls inside, to get a real **percentage of households who clear the bar**, not a yes/no.

`apply_affordability_gate()` then scales the feasibility-adjusted unit count by that percentage — multiplicative, not a second binary toggle, and explicitly stacked with (not a substitute for) the absorption rate: affordability narrows *who could ever pay* for a unit; absorption rate narrows *how many of those who could, actually do, in a given year*. Both this mortgage-only P&I calculation (excludes property tax, insurance, HOA/CPR fees — a stated understatement of the true income bar, since no Hawaii-specific tax/insurance source is in this project yet) and the one-sided revenue-only price scaling inherited from the feasibility gate are stated simplifications, not hidden ones.

**Result, and it is not a small correction.** Countywide, at the ADU/Missing Middle for-sale product's comps-implied prices, **0% of Kauai households clear the required-income bar in every single tract** — the feasibility-adjusted 108.2 ADU units and 2,937.6 Missing Middle units both collapse to **0 affordability-constrained units** countywide. The underlying pattern explains why: the tracts where a project is *feasible* to build (comps support a high enough sale price to cover cost + developer profit) are disproportionately Kauai's expensive tracts (Princeville/Hanalei North Shore, etc.) — $1.9M+ required sale prices, $400K+ required household income, which essentially no Kauai household has. The tracts with *lower*, more locally-affordable prices are, under this cost structure, the ones that fail feasibility in the first place (the comps-implied price doesn't clear the Lihu'e-sourced cost structure). There is essentially **no overlap** between "a developer could profitably build this" and "a Kauai household could afford to buy it" for the for-sale ADU/Missing Middle product as currently modeled. TOD's rental product fares less badly (28–34% of households clear the rent-affordability bar in most tracts, since $3,708/month is a much lower bar than a $1M+ sale price) — countywide the FAR=4.0 feasibility-adjusted 190,779 units falls to **52,185 affordability-constrained units**, a real ~73% cut, on top of the magnitude problem already flagged above.

This is a genuine finding about Hawaii's housing-affordability crisis, not a modeling artifact to be explained away — but it does mean the for-sale feasibility gate, as currently built, is testing "can a developer profitably build a product priced for second-home buyers," not "can this reform produce housing locals can afford." The dashboard now shows all three numbers side by side (zoning capacity → feasibility-adjusted → affordability-constrained) with a third toggle and a tract-level "% of households affording" tooltip, rather than quietly computing a worse number and reporting only the better-looking one upstream of it.

2. **Because revenue scales linearly with each tract's own home value relative to the countywide median, a tract needs to sit roughly 34% above that median just to break even.** The cutoff is sharp: a $1,079,100-median tract fails (`excess_value_usd` = -$1,941), a $1,085,300-median tract passes (+$2,269). All 44 feasible tracts fall in the $1.085M–$2.0M range — Honolulu's priciest neighborhoods (East Honolulu, Kahala-type areas, North Shore).

**Skyline's real corridor doesn't reach that price tier at all.** The rail-eligible tracts (Kapolei, Waipahu, Pearl City, Kalihi, Kapalama, Iwilei, Chinatown, Downtown — Skyline's actual, real station list) top out at a $961,700 median home value, below the ~$1.08M breakeven threshold everywhere. This is not evidence that transit-oriented redevelopment near Skyline is infeasible in reality — it's evidence that this specific for-sale pro forma's cost structure (HR&A's own table figures, not calibrated for this use) doesn't pencil anywhere along Skyline's real corridor, which runs through Oahu's working/industrial urban geography rather than its most expensive neighborhoods. **Open next step, not yet built:** a rental-product pro forma for the Skyline corridor specifically (consistent with the project's standing caveat elsewhere that no multifamily rental pro forma exists yet for either county's TOD scenario) would likely be the right fix, rather than continuing to apply a for-sale product priced for a market the rail line doesn't physically pass through.

Honolulu's pattern differs structurally from Kauai's: Kauai's for-sale product clears feasibility in most tracts but then collapses to 0% affordability everywhere (the feasible tracts are uniformly too expensive for any local household); Honolulu's gate is the opposite bottleneck — a minority of tracts (44 of 288) clear feasibility at all, but among those that do, a real share of households (not 0%) can afford the result. Both findings are real, sourced outputs of the same gate mechanism applied to each county's own real ACS/pro forma inputs — not a modeling artifact reconciled to look similar across counties.

## Every reform now competes on BOTH tenures: dual-tenure feasibility and the "closing the loop" affordability split (2026-10-15, next day's work)

Once a real rental test existed alongside the real for-sale test, the user asked the obvious next question directly: *"how do we account for the differences between the feasibility gap of for sale vs rental? If either one is feasible do we just assume it's going to get built? Do we then close the loop to say that by enacting such and such policy, it would likely create housing for either renters or for sale units at these different income bands?"*

**The answer implemented is neither "either feasible → built" nor "sum the two."** Letting a tract count as feasible whenever EITHER pro forma clears would double-count — the same unit of zoning capacity would be reported once as a for-sale outcome and again as a rental outcome, when in reality a developer builds one product on a given parcel, not both. The correct mechanism, implemented in `build_model.combine_dual_tenure_feasibility(for_sale_df, rental_df)`:

1. Run both the for-sale pro forma (`tract_scaled_development_fee_reduction_feasibility()` / `tract_scaled_oahu_development_fee_reduction_feasibility()`) and the rental pro forma (`tract_scaled_rental_feasibility()`) for every tract.
2. Take `excess_value_usd = max(excess_value_for_sale, excess_value_rental)` per tract, and tag `winning_tenure` with whichever one produced it.
3. `feasible = excess_value_usd >= 0`, same as before — but now it's the winning tenure's test, not an arbitrary single-tenure assumption.

This is applied to every reform that has a feasibility gate — ADU, Missing Middle, and TOD (both modes), in both counties — rather than hardcoding ADU/Missing Middle to for-sale and TOD to rental as the prior round did. That prior hardcoding was itself an unstated assumption: nothing about ADU or Missing Middle zoning makes the resulting unit a for-sale product rather than a rental one (a duplex built under Missing Middle, or even an ADU, is at least as plausibly rented out as sold separately), and nothing about TOD-zoned land makes it only ever a rental apartment building rather than a condo tower. Letting both compete and taking the winner is the honest version of "whichever a developer would actually choose to build."

**"Closing the loop":** `build_model.apply_dual_tenure_affordability_gate()` routes each tract's feasibility-adjusted units through the correct income distribution for whichever tenure won that tract — for-sale-won tracts check the real ACS B19001 owner/all-household income brackets (same mechanism as before); rental-won tracts check the real ACS B25118 renter-occupied-household brackets. Because `winning_tenure` is set once per tract by the feasibility step, each tract's units are tested against exactly one income distribution, never both and never neither — the same non-double-counting discipline carried one step further downstream. The function returns both a combined `affordability_adjusted_units` figure (so existing code that expects one number still works) and `affordability_adjusted_units_for_sale` / `_rental` breakouts, which is what actually answers "would this create housing for renters or for owners, and at what income band":

Tenure-win counts among feasible tracts: Kauai 12 for-sale / 1 rental (of 17 tracts); Honolulu 38 for-sale / 79 rental (of 288 tracts with both tests available). Two real findings fall out of this, stated plainly:

- **Kauai's affordable housing, under either tenure, is overwhelmingly rental, not for-sale** — the for-sale affordability gate has been 0% in every single Kauai tract since this project's first feasibility pass (no sale price any feasible tract can support is in reach of any real Kauai household's income), so even though for-sale pencils as the more profitable product in 12 of 17 feasible Kauai tracts, essentially none of that capacity converts into affordability-constrained units; virtually all of Kauai's affordable outcome comes from the minority of tracts where rental wins the feasibility test.
- **Honolulu's result is a genuine mix** — a real, nonzero for-sale affordability contribution now shows up (157.0 ADU units, 796.7 Missing Middle units, 13,518.7 TOD-bus units) alongside the larger rental contribution, meaning Honolulu's reforms would plausibly create BOTH owner-occupied and rental housing, at different income bands, in different tracts — a materially more informative statement than a single blended number.
- **TOD-rail's result is unchanged (0.0 for-sale)**: HART Skyline's 13 open stations sit in Honolulu's industrial/working corridor, where the for-sale pro forma (calibrated to the county's priciest neighborhoods) never clears regardless of being allowed to compete — confirming, rather than contradicting, this round's earlier diagnosis.

**STATED SIMPLIFICATION, carried forward honestly:** a tract where BOTH tenures pencil is winner-take-all (100% of that tract's capacity tagged to whichever excess value is larger), not split between the two. The economically more accurate version would split a tract's capacity by a real local multifamily-rental-vs-for-sale permit-mix ratio for that submarket; no such tract-level source is in this project yet, so this states the simplification rather than inventing a split ratio. Likewise, applying the SAME single rental pro forma (the Skyline TOD study's apartment-building economics) to ADU and Missing Middle as to TOD is a real, stated reuse of one calibrated reference product across very different physical products (a single accessory unit vs. a multifamily building) — the same evidentiary status the for-sale townhome reference product already carries when applied to all three reforms, not a new or hidden assumption.

## The baseline scenario itself, not just the intervention (2026-10-16)

The user's direct instruction: *"we need to develop both the baseline scenario and the scenarios with the zoning interventions. we are well on our way with the zoning interventions but haven't developed the baseline scenarios based on existing zoned capacity."*

This project's baseline/intervention principle (never report a reform's total capacity as the incremental impact) was already being followed as a SUBTRACTION step inside every reform — but the baseline figure being subtracted was never itself computed correctly everywhere, nor reported as its own number anywhere. Two real fixes:

**1. Missing Middle's baseline is now reported, not just used internally.** `run_missing_middle_baseline()` has computed each parcel's `baseline_capacity` (what today's zoning already legally allows beyond what's built) since the buildable-area work earlier this project — but only to decide which parcels are even eligible for the Missing Middle reform (`baseline_capacity == 0`, i.e. currently single-family-restricted). The actual MAGNITUDE of `baseline_capacity` on parcels where it's positive — current zoning already permits more units than exist, no reform needed — was computed and then discarded. New function `run_missing_middle_baseline_tract(county)` rolls that figure up to the tract level and reports it as its own number:

- **Kauai: an estimated 1,922.8 units** (30,521 gross units of legal headroom across 3,160 parcels, scaled by the 6.3% absorption-rate benchmark) that today's zoning already allows beyond what's built — before any Missing Middle reform at all. This is a real, substantial number sitting alongside the reform's own 2,899.1 feasibility-adjusted additional units: Kauai's zoning already has meaningful unused legal capacity, separate from and larger in gross terms than what Missing Middle itself would add.
- **Honolulu: 0 everywhere.** This is the coarser, label-based baseline method (`use_rdistrict_density_rule=False` — no sourced density-per-acre rule exists for Honolulu's R-districts, so a parcel is either single-family-restricted (`baseline_capacity == 0`) or outside this test's scope (`NA`) — never credited with positive headroom). **Stated plainly: this is a real data gap, not a finding that Honolulu's current zoning has no unused capacity.** Honolulu's actual Table 21-5.1 Duplex-/Two-Unit-Dwelling permission rows (not yet re-verified against the real ordinance text) may already permit more than 1 unit by right in some of these districts — exactly the finer distinction flagged as unconfirmed since the Missing Middle baseline was first built.

**2. TOD's baseline was actually wrong, not just unreported — now fixed.** `run_tod_scenario()` computed `additional_capacity = max(0, reform_capacity - existing_units_estimate)`, where `existing_units_estimate` is what's physically BUILT on a parcel today. That's the wrong baseline for a zoning-capacity question: a parcel whose CURRENT (non-TOD) zoning already permits more units than are built has real, unused legal headroom under TODAY's law — crediting that headroom to the TOD reform overstates what TOD's FAR bonus actually unlocks, the same mistake this project's core principle exists to prevent, just hiding one level deeper (in what gets subtracted, not whether a subtraction happens at all). Fixed: `true_baseline = max(existing_units_estimate, max_units_by_density)` — built units OR today's zoned capacity, whichever is larger, using the SAME `max_units_by_density` field Missing Middle's baseline already uses, so both reforms are now measured against a consistent definition of "what current law already allows."

Real effect of the fix: Kauai TOD (bus) drops from 137,280.1 to **136,578.6** raw units (a real but small correction — most TOD-eligible Kauai parcels don't carry much unused current-zoning headroom). Honolulu TOD (both modes) is **unchanged** — 824,806.2 (bus) / 72,240.1 (rail) — because the same missing Honolulu density-per-acre data that makes Missing Middle's baseline 0 also makes `max_units_by_density` 0 for every Honolulu parcel, so `true_baseline` reduces to `existing_units_estimate` there regardless. Both results are the honest, correct behavior of the fix, not an inconsistency: the fix only changes the number where real zoned-capacity data exists to change it against.

**What this does NOT yet do:** ADU's own reported number already functions as a true baseline scenario by construction — `ScenarioParams()` with every field at default reproduces current law (Act 39/SB3202's 2-ADU-per-lot mandate) exactly, per `ScenarioParams.is_baseline`, so no separate "ADU baseline" needs computing. `run_adu_policy_impact()` (comparing that baseline against a hypothetical intervention, e.g. `allow_non_single_family_zones=True`) exists in `build_model.py` but is not yet wired into the dashboard UI as a user-facing slider/toggle — that remains the next real step if ADU is to get its own explicit reform-vs-baseline comparison the way Missing Middle and TOD now do.

# Data Sources and Cleaning Steps

Full dataset-by-dataset provenance, licensing, and access dates live in `docs/DATA_PROVENANCE.md` (the Dataset Inventory table) and `data/DATA_SOURCES.md` (the narrative citation/rationale for each). In summary, four families of data feed this model:

1. **Parcel-level geospatial data** (statewide GIS: TMK parcels, county zoning, State Land Use Districts, building footprints, Census tracts) — joined by centroid-in-polygon at the parcel level, reprojected to UTM Zone 4N (EPSG:32604) for consistent area math, then bucketed and rolled up to tract level. See "Buildable-area methodology" above for the full pipeline.
2. **County-specific real property/assessor data** (Honolulu's `CadastralTables`/`LEGDAT`, Kaua'i's tax-class field) — used to establish existing-unit counts and occupancy status where each county's data supports it; gaps are explicitly logged rather than papered over (see "Existing units and building size" above).
3. **Federal/state statistical data** (Census ACS income distributions, Census Building Permits Survey, HUD USPS address-vacancy data, Hawaii DBEDT housing-unit estimates) — used for statewide-consistent denominators (current housing stock, absorption-rate benchmarks) and the affordability gate's income-distribution lookups.
4. **Hawaii-specific planning and ordinance documents** (county ADU ordinances, Honolulu's Revised Ordinances Chapter 21 FAR tables, HB1409/Act 159 statutory text, the State OPSD's TOD financial-analysis reports, DPP's own TOD demand-analysis report) — hand-digitized into named, cited constants rather than scraped, since these are legal/planning text, not structured data.

Cleaning followed one rule throughout: **when a gap or inconsistency was found, it's logged here with the date it was found and how it was resolved** (or left open, if unresolved) — see the dated sections above for the specific history (e.g., the `ovrclass` decoding dead-end, the Honolulu sales-join GEOID-type bug, the TOD overlay's distance-buffer-to-real-rezoning rebuild).

# Methodological Approach

**The governing principle, applied to every scenario without exception: baseline and policy intervention are always computed and reported separately.** A scenario's headline number is never "the reform's total legal capacity" — it is `additional_capacity = max(0, reform_capacity − true_baseline)`, where `true_baseline` is whichever is larger: what's actually built today (`existing_units_estimate`) or what today's *non-reform* zoning already legally permits (`max_units_by_density`). This matters because a parcel can have substantial unused capacity under *current* law — crediting that to a reform would overstate the reform's real, incremental effect. This fix was applied retroactively to every scenario in this model (Missing Middle, TOD overlay, ADU) after being caught in one scenario first; see the dated correction notes throughout this document and `docs/DATA_PROVENANCE.md`'s Known Limitations section for the specific history of each.

**Pipeline, scenario-agnostic:**
1. `build_county()` runs once per county: spatial joins (parcel ↔ zoning ↔ State Land Use District ↔ tract ↔ building footprint), producing `{county}_parcel_level.csv` — every parcel's zoning, land-use district, tract, coverage ratio, remaining buildable area, existing-unit estimate, and current-law maximum density-based capacity.
2. Each scenario function (`run_adu_scenario()`, `run_missing_middle_scenario()`, `run_tod_scenario()`, `honolulu_tod_overlay_capacity_tract()`, `run_parking_reform_scenario()`, `apply_development_fee_reduction()`) reads that same parcel table, applies its own eligibility rule (e.g. "Urban district, lot ≥ X sqft, not already multi-unit") and its own reform mechanism (e.g. a new FAR tier, a relaxed density cap), computes `reform_capacity`, subtracts `true_baseline`, and rolls up to tract level.
3. Two further gates can be layered on top of any scenario's raw capacity, each answering a different question: **feasibility** (`tract_comps_development_fee_reduction_feasibility()` and related functions — would a developer actually turn a profit building at the comps-implied sale price, given real construction-cost and financing inputs?) and **affordability** (`tract_affordability_constrained_capacity()` + `apply_affordability_gate()` — of the households who could theoretically buy/rent at that price, what share of the tract's *own* households clear that income bar, per real ACS income distributions?). These are multiplicative scaling factors on the raw capacity number, not independent metrics — a scenario can be legally permitted, infeasible to build, and unaffordable to local households all at once, and the model is built to show all three rather than collapsing them into one number.
4. The **absorption rate** (county-specific, sourced from real permit-pace data) scales raw eligible capacity down to a *plausible build-out* estimate over a 10-year horizon — the step that turns "how many units could legally exist" into "how many would actually get built at this area's historical pace," which is the number most relevant to a policymaker's planning horizon.

**TOD overlay, Honolulu-specific (the one scenario with its own distinct data path):** Honolulu's TOD rezoning is modeled two ways, for two different purposes, and the two are **not** interchangeable:
- The Existing Conditions dashboard's TOD card (`honolulu_tod_adopted_zoning_parcels()` / `honolulu_tod_overlay_capacity_tract()`) uses the real, as-adopted TOD rezoning polygons (186 features, City & County of Honolulu) and the Revised Ordinances of Honolulu's actual Chapter 21 FAR tables for each parcel's real rezoned code — this answers "what does the TOD rezoning the City already adopted actually allow, parcel by parcel?"
- The Scenario Explorer's TOD intervention (`run_tod_scenario(mode="rail")`) models a *different* legal mechanism: Act 159/HB1409's 2025 statewide FAR-bonus-near-transit statute, using real transit-stop distance and the statute's own 6.0/7.0 FAR tiers — this answers "what would the 2025 state law allow near any real transit stop?"

Both are grounded in real adopted law, but they are different laws with different FAR values and different eligible footprints, so their outputs are not meant to be added together or substituted for each other. DPP's own planning-stage estimate for the TOD plan areas (~62,215 units, from an independent 2019 demand-analysis report) is cited as an order-of-magnitude cross-check on the first figure (86,191 units) — see `docs/DATA_PROVENANCE.md` — but is not itself a model output.

# Limitations and Known Edge Cases

- **This model's parcel/scenario pipeline now covers all four counties (added Hawai'i County and Maui County 2026-10-24), but the live dashboard still only surfaces Honolulu and Kaua'i.** `scripts/build_model.py`'s `COUNTY_CONFIG` entries for `"hawaii"` and `"maui"`, their ADU-eligibility rules (Hawai'i County's Bill 123; Maui's Ordinance 4936), and `build_county()` have all been run and sanity-checked against live data — but `scripts/build_dashboard_data.py` (the script that produces the JSON `index.html` actually reads) has a large, hand-built, per-county section for Kaua'i and Honolulu only, and has not yet been extended to the other two. Any statewide total the *dashboard* implies should still be read as "Honolulu + Kaua'i," not all four counties, until that wiring is done — a distinct, scoped remaining task, not a data gap.
- **Hawai'i County's `pittcode` decode is now CONFIRMED against an authoritative source (updated 2026-10-26); Maui's is still an unconfirmed working hypothesis.** Both counties' raw parcel data expose a numeric `pittcode` field rather than Kaua'i's text `taxclass` or Honolulu's `ovrclass`. For Hawai'i County, the county's own official ArcGIS item description ("County of Hawai'i Properties as of April 2025," Real Property Tax Office / Planning Department) now confirms: Residential (100), Apartment (200), Commercial (300), Industrial (400), Agricultural or Native Forests (500), Conservation (600), Hotel and Resort (700), Homeowner (900), Multiple codes for a single TMK (999), or Unknown/Affordable Rental Housing (0) — the model now includes 0 in `existing_residential_taxclasses` (Affordable Rental Housing is residential), correcting an earlier guess that treated 0 as a non-residential sentinel. Maui's identical-looking `pittcode` field has not had an equivalent authoritative source found yet, so it remains an unconfirmed hypothesis — the same epistemic status as the `ovrclass` 11/14 codes flagged elsewhere in this document. Maui's higher codes (1000/1100/1200) fall outside even that hypothesis and are treated as unclassified rather than guessed at.
- **Centroid-in-polygon spatial joins are an approximation, not full polygon overlay.** A parcel whose centroid sits in one zoning district but whose shape spans two will be misclassified; this is the standard trade-off at this feature count and is not expected to materially change county-level totals, but it is a real source of parcel-level error, especially along district boundaries.
- **The TOD overlay's eligibility is "was this parcel actually rezoned into one of the adopted TOD codes," not "is this parcel inside the TOD planning-area boundary."** A parcel inside the TOD plan area that was never rezoned into an AMX/BMX/IMX code gets zero TOD-specific capacity from this model — which is correct for "what does the adopted rezoning allow" but means this figure is not the same as, and is smaller than, DPP's own planning-area capacity estimate (see above).
- **Permit-data quality is not uniform across counties, and this model does not paper over that.** Honolulu's and (as of 2026-10-26) Maui's ADU scenarios now use real, permit-calibrated absorption rates (`honolulu_real_adu_absorption_rate()`, `maui_real_adu_absorption_rate()` in `build_model.py`); Kaua'i's and Hawai'i County's ADU scenarios still use the generic all-housing benchmark, for two different reasons (no comparable Kaua'i permit dataset exists at all; Hawai'i County's does exist but calibrating against it would be calibrating against an abolished permit process -- see below). Maui's calibration is real but weaker than Honolulu's on two specific counts, disclosed in `maui_real_adu_absorption_rate()`'s own docstring rather than smoothed over: it's extrapolated (avg monthly rate x 12) from 30 months spanning 3 calendar years (2026-10-27: 10 of 12 months of 2024, all of 2025 except February, plus Jan-Sep 2026 -- the missing months excluded due to unrecoverable broken source-PDF text layers, not estimated) rather than an average of multiple COMPLETE years, and it identifies ADU permits by a free-text keyword match on the permit description (Maui's report has no dedicated ADU/Ohana permit-type field), which is a lower bound, not an authoritative count. The four counties' ADU scenarios therefore still do not share one absorption-rate methodology end-to-end, and now span three distinct confidence levels (Honolulu: real, multi-year, authoritative field; Maui: real, 30-month/3-year, free-text proxy; Kaua'i/Hawai'i County: generic benchmark) -- a genuine, disclosed limitation of the underlying data landscape, not a modeling inconsistency this project introduced.

### Why this gap matters more than it might first appear, and what it would take to close it

This isn't a minor data-completeness footnote — it's evidence of a real risk that generalizes beyond the ADU scenario. Three findings from investigating it directly (2026-10-23/24), each worth stating plainly:

1. **The remaining uncalibrated counties' (Kaua'i, Hawai'i County) absorption-rate gap is probably not simply "lower regional appetite for ADUs" — it's partly a mechanical artifact of how differently each county's own eligibility rule is scoped.** Honolulu's ADU ordinance has no lot-size minimum (confirmed against ROH 21-5.50-3(a)), so its eligible-parcel pool is enormous and unselective (136,684 parcels — essentially the entire single-family-zoned stock). Kaua'i's ordinance requires a 7,500 sqft minimum lot, so its eligible pool is already narrow and self-selected (2,297 parcels). The generic benchmark (all housing permits ÷ total housing stock) was never scoped to "ADU-eligible parcels" in the first place, so applying it as a stand-in produces a *larger* per-parcel rate for a *narrower*, more selective eligible population almost mechanically — independent of whether residents in one county actually want ADUs more or less than residents in another. This means **Honolulu's real 1.55% rate (or Maui's real 8.5%) cannot simply be transplanted onto Kaua'i or Hawai'i County** as a "better" number — that would trade one unvalidated figure for a different unvalidated figure, now dressed up with false precision. Every scenario in this model is already a cascade from legal maximum toward a realistic estimate (eligibility → feasibility → affordability → absorption rate); what differs between a calibrated county's ADU figure and an uncalibrated county's isn't that one is "the maximum" and the other is more honest about being capped — all four go through the same cascade. What differs is *confidence in one specific input to that cascade* (the absorption rate), not the shape of the estimate itself. (Maui's real 8.5% decade-equivalent rate, incidentally, lands close to its own generic benchmark of 10.4% -- a useful sanity check that the generic benchmark wasn't wildly off for Maui specifically, even though it was never designed to answer the ADU-eligible-parcel question directly.)
2. **Hawai'i County and Maui County were directly investigated for an equivalent open dataset, not just assumed unavailable.** **Correction, 2026-10-26:** an earlier version of this document said Hawai'i County's "Ohana Permits" GIS layer sat behind an internal ArcGIS Enterprise portal requiring a county-granted login. That was wrong — this project's own search tooling simply hadn't found the real public endpoint. The user supplied the correct public-facing ArcGIS Hub link directly; tracing it to its underlying ArcGIS Online item confirmed a genuinely public FeatureServer (`services1.arcgis.com/.../ohanapermit/FeatureServer/16`, 4,057 real, TMK-keyed permit-application records, no token required) and, separately, the county's own official PITT-code documentation (resolving the `pittcode` decode above from a guess to a cited fact). **This dataset turned out NOT to be usable for calibrating a future absorption rate anyway, but for a substantive reason, not an access reason**: it records applications under the OLD "Ohana Dwelling" permit process, which Ordinance 24-70 (Bill 123 Draft 5, effective 2026-10-07 — the primary ordinance text, fetched directly from the County Clerk's own WebLink system) repealed and replaced. Annual permit volume under that old process collapsed from the hundreds per year (peak 541 in 1989) to single digits per year every year from 1996 through 2023, almost certainly reflecting the old process's own administrative friction (a separate application track, $25 fee, a one-active-application-at-a-time rule, a 10,000 sqft minimum lot — all since repealed) rather than real demand. Using that collapsed rate to calibrate the *new*, deliberately-loosened ordinance's future absorption would understate it, probably severely — so Hawai'i County's ADU scenario still uses the generic county benchmark, now with the real historical data disclosed (`hawaii_county_historical_ohana_permit_summary()` in `build_model.py`) rather than omitted. Maui County's public ArcGIS catalog is genuinely open (no token required) for parcels, zoning, and State Land Use data, and the `DSA` (Development Services Administration) itself publishes monthly "Building Permits Issued" detail reports as PDFs — not via an API or bulk export (the DocumentCenter hosting them returns HTTP 403 to automated fetches, confirmed 2026-10-26), but the user supplied them directly, and `scripts/process_maui_permit_reports.py` now parses 30 months (10 of 12 months of 2024, all of 2025 except February, plus Jan-Sep 2026) of them into real, TMK-joined permit records, which `maui_real_adu_absorption_rate()` uses to calibrate Maui's ADU scenario (see above). This is a weaker calibration than Honolulu's (30 months spanning 3 calendar years, none complete, rather than multiple full years; free-text ADU identification rather than a dedicated field) but a real one. **None of the four counties lacks real permitting activity or a real underlying system; what's still missing for Kaua'i and Hawai'i County is a public, structured, CURRENT-ordinance-relevant export of it**, the same kind Honolulu already publishes and Maui's user-supplied reports now substitute for.
3. **The fix is not more modeling effort — it's standardized, structured, public permit data from each county, published the way Honolulu already does it.** Honolulu's dataset works for this purpose specifically because it's individual-record-level (not aggregated), has an explicit, unambiguous ADU/Ohana flag (not a keyword search that has to be inferred), and is reachable without authentication. A statewide standard for this — even just matching Honolulu's own schema across the other three counties — would let every county's ADU scenario (and likely other scenarios' absorption rates too) be calibrated the same way, closing exactly the asymmetry this section describes. This is a genuine, actionable, low-cost policy/IT recommendation independent of anything this specific tool can do: **the state or counties publishing uniform, high-quality, structured permit open data would directly and measurably improve the reliability of tools like this one** — not a hypothetical benefit, but a concrete, demonstrated one, visible in the >3x gap between Honolulu's calibrated and uncalibrated figures.
- **Absorption-rate benchmarks (where no scenario-specific real data exists) measure total permits against total existing housing stock, not permits against an eligible-parcel universe under a specific reform.** No historical eligible-parcel baseline exists for Hawaii for any of these reforms (none have been in effect long enough), so this is the best available empirical proxy, not a validated absorption rate for any one scenario.
- **The affordability gate's rental-tenure comparison uses a single countywide Zillow rent figure (ZORI), not a tract-level rent.** No tract-level Kaua'i rent source exists, so every tract in a rental-tenure comparison is checked against the same required-income bar, even though real rents vary by tract. The for-sale comparison does not have this limitation — it uses each tract's own comps-implied sale price.
- **Parking-requirement reduction's effect is not quantified as a single number** — deliberately, because the cited multi-city study shows the real effect varies by density and car-dependency context, and a single "$/space" or "% capacity increase" figure would misrepresent that variation as uniform.
- **HUD's USPS-derived current-stock figure is a delivery-point proxy, not a certified housing-unit count** — undercounts multi-unit buildings sharing one mailbox, and can occasionally miscode a commercial address as residential.

# Sensitivity Notes

The inputs that move results the most, in order:

1. **Absorption rate** — this is the single largest lever on every scenario's headline "estimated units" figure, since it is a direct multiplier on eligible capacity. The county-specific benchmarks span more than 2x (5.0% Honolulu to 11.0% Hawai'i County), so using a single statewide default instead of each county's own benchmark would materially misstate results in either direction. **Within a single county and scenario, swapping a generic benchmark for a real scenario-specific one moved the result even more**: Honolulu's ADU scenario drops from 6,834 to 2,118 estimated units (same 136,684 eligible parcels) once the absorption rate switches from the generic 5.0% county benchmark to the real, permit-calibrated 1.55% ADU-specific rate — a >3x swing from a single input, and a concrete illustration of why this model avoids a single statewide absorption-rate default.
2. **Minimum lot size (ADU scenario)** — sweeping Kaua'i's `min_lot_sqft` parameter from 5,000 to 15,000 sqft changes eligible parcels from 15,395 down to 3,020, a >5x spread. This is the single most sensitive eligibility parameter in the model and is exposed as a slider for exactly this reason.
3. **Owner-occupancy requirement (ADU scenario, Kaua'i only)** — toggling this on roughly halves eligible parcels (11,351 → 5,960 at default lot size). Only Kaua'i's tax-class data currently supports this toggle; the other counties' fields don't distinguish owner- from non-owner-occupied, which is itself a sensitivity worth noting (the same toggle would behave differently, or not at all, in another county).
4. **Development-cost inputs by county (feasibility gate)** — Honolulu's ~6x higher land cost per GSF versus Kaua'i's materially changes which tracts clear the feasibility bar at the same sale price; a statewide-average cost input would misstate feasibility in both counties.
5. **TOD overlay eligibility footprint** — narrowing from "within the TOD planning area" to "actually rezoned into an adopted TOD code" cut this scenario's gross capacity from an earlier, overbroad buffer-based estimate (~1.44M units, since retired) to 86,191 units — the single largest magnitude correction in this model's history, and a reminder of how much a capacity scenario's result depends on how tightly "eligible" is defined.

# Intended Users and Appropriate Use Cases

**Intended users:** state and county policymakers and planning staff evaluating the likely housing-production impact of specific, named Hawaii zoning reforms (ADU/Ohana mandates, Missing Middle upzoning, Honolulu's TOD rezoning, parking-minimum reduction, development-fee reduction) — people who need an order-of-magnitude, defensible estimate of "how many more housing units would this change plausibly produce," broken down by county and by legal mechanism, to compare reform options against each other.

**Appropriate uses:** comparing the relative scale of different reform levers within Honolulu and Kaua'i; understanding which parameters (absorption rate, lot-size minimums, owner-occupancy rules) a specific reform's design choices are most sensitive to; identifying which tracts or areas a reform would concentrate its effect in; using the feasibility and affordability gates together to see where legal capacity, financial feasibility, and local affordability diverge.

**Inappropriate uses:** this tool should **not** be used to produce a single statewide housing-need number from the live dashboard (it currently surfaces Honolulu and Kaua'i only — see Limitations); to assert a precise unit count for any specific tract or parcel (every figure here is a modeled estimate built on proxies and benchmarks, not a certified count); to treat Hawai'i County's or Kaua'i's ADU-scenario figures as being on equal calibration footing with Honolulu's or Maui's, since the former two still use the generic county benchmark rather than a real permit-calibrated rate, and to treat Maui's real calibration as being on equal footing with Honolulu's, since Maui's is extrapolated from 30 months spanning 3 calendar years (none complete) using free-text ADU identification rather than Honolulu's multi-complete-year, authoritative-field calibration (see Limitations); to compare Honolulu's TOD overlay figure directly against the Scenario Explorer's statewide TOD intervention figure, since they model two different laws (see Methodological Approach above); or as a substitute for site-specific feasibility analysis before any individual development decision.
